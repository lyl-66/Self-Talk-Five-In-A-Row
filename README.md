# Self-Talk-Five-In-A-Row

**五子棋 · 人机对战** —— 用 Godot 4.7 + GDScript 写的单人对战五子棋。

一个棋盘主窗口，外加四个可以各自关掉、独立存在的小窗口（比分、对话、设置、音乐）。比分长期保存在玩家的用户目录里；对手**每局说一个话题**，落一子说一句，棋局结束话题也结束。先后手、对手棋力、禁手规则和界面配色都在设置窗口里开关，台词写在 `topics.txt` 里；音乐窗口放的是 `music/` 里随游戏一起打进来的歌，**另外还有一个玩家自己的音乐文件夹**（`user://music/`，窗口上有一键打开），想加歌就加在那儿。

## 玩法

- 15 × 15 棋盘，在交叉点落子
- 默认**玩家执黑先手**；可以在设置里换成玩家执白后手（那样对手执黑先下）
- 横、竖、斜任意方向先连成五子者胜，棋盘下满判和棋
- 默认是自由规则，无禁手（长连也算胜）；打开「禁手规则」后按连珠规则判罚，见下文

操作：鼠标移到交叉点上会显示半透明预览，左键落子。棋盘上那个红点是对手的最后一手。每落一子会响一声（`sound/落子音效.mp3`，玩家和对手都响；**音量在音乐窗口里那条「音效」上调**）。

> 隐藏组合键（都是按一下切过去、再按一下切回来）：<kbd>Shift</kbd>+<kbd>5</kbd> 解锁全部窗口 ←→ 完全归档；<kbd>Shift</kbd>+<kbd>6</kbd> 给落子音效加一层混响 ←→ 恢复干声（彩蛋）。

## 运行

需要 [Godot 4.7](https://godotengine.org/download)：

```bash
godot --path .
```

或者用编辑器打开 `project.godot` 后按 <kbd>F5</kbd>。

## 五个窗口

| 窗口 | 尺寸 | 说明 |
| --- | --- | --- |
| 主窗口 | 720 × 720 正方形 | 棋盘 + 一行状态提示 + 左上角「设置」小按钮 + 右上角「音乐」小按钮 + 底部三个按钮 |
| 比分窗口 | 380 × 400 | 累计比分（玩家 / 对手 / 和棋）和最近一局摘要，可清空 |
| 对话窗口 | 380 × 400 | 对手每落一子在这里说一句；一局一个话题，结束时收尾 |
| 设置窗口 | 380 × 400 | 先后手、棋力开关、禁手开关、三处配色 |
| 音乐窗口 | 380 × 400 | 歌单、曲名、播放条、暂停/播放、下一首（见下节） |

四个小窗口**尺寸一致**，行为也一致：

- **都能自由缩放，且内容等比跟随**：拉大时字和控件一起放大，缩小时一起缩小；另外拉伸模式是 `expand`，多出来的区域由界面铺开，**不会出现黑边**
- **启动时回到上次的位置、尺寸和开关状态**：上次关掉的小窗口这次仍是关着的，点主窗口对应按钮就能打开
- 第一次启动（还没有记录时）四个小窗口会摞在主窗口右边**竖排，不会互相叠着**；屏幕右边放不下就自动挪到主窗口下方

主窗口同样不留黑边：棋盘会重新摆到正中，顶部提示行和底部按钮行跟着窗口宽度重新居中。右上角那个「音乐」按钮和左上角的「设置」同宽同高，**各贴自己那一侧的窗口边缘**——两个按钮离同侧边缘的间距一样，窗口怎么拉都对称（间距是画布单位，`canvas_items` 拉伸下会跟着等比缩放）。

### 窗口是打出来的

新玩家开局**四个小窗口都是锁着的**，而且**主窗口上根本不显示对应的按钮**——赢一把冒出来一个，不会一上来就看到一堆点不动的灰按钮。按**累计胜场**逐个解锁：

| 赢到第几把 | 解锁 |
| --- | --- |
| 1 | 对话窗口 |
| 2 | 音乐窗口（音乐和音效两条音量都在里面） |
| 3 | 设置窗口 |
| 4 | 比分窗口 |

主窗口、棋盘和「重新开始」一直可用，锁的只是四个窗口的入口。

几点说明：

- **解锁进度只增不减**，单独记在 `settings.cfg` 的 `[unlocks] level`，不跟着胜场走。
  所以用比分窗口的「清空」把胜场归零，**不会**把已经开出来的窗口又锁回去。
  同理，设置窗口的「恢复默认」也不会动它。
- **应急通道：<kbd>Shift</kbd>+<kbd>5</kbd>**（就是打出 `%` 的那个组合）是**切换**：
  按一下解锁全部窗口并写进存档记住，再按一下**完全归档**——把 `settings.cfg`、`score.cfg`、
  `windows.cfg`、`history.jsonl`（连历代「清空比分」留下的旧明细）一起搬进
  `user://archive-<时间戳>/`，游戏回到从没玩过一把的样子。**是搬走不是删除**，
  想反悔去那个目录把文件挪回来就行。
  判断用的是**物理键位**而不是字符，所以在别的键盘布局上也按同一个组合就行。

## 音乐播放器

主窗口**右上角**的「音乐」按钮打开播放器：

- 顶上显示**当前曲名**
- 一条**播放条**，拖动可以定位；右边写着 `已播 / 总长`
- 一条**音量条**（管音乐）
- 一条**音效条**（管落子声这类游戏音效）
- 「暂停 / 播放」和「下一首」
- 下面是**歌单**：先分两组（我的音乐 / 出厂音乐），组里再按子文件夹分组，每个文件夹一行、后面写着有几首，
  **点一下展开或收起**，展开后才看得到里面的歌；点歌就播放
- 一个**「打开文件夹」**按钮：直接跳到玩家自己的音乐目录

两条音量各走各的播放器，互不影响：把音乐拉到 0，落子声照响；反过来也一样。
歌单里**文件夹是亮的、里面的歌压淡一档**，一眼能分出哪几行是「装东西的」。
（两条音量都只活在本次运行里，关掉游戏就回到默认大小。）

行为：

- 一首放完**自动下一首**，最后一首放完回到第一首。「下一首」按歌单摊平后的顺序走
  （我的音乐在前、出厂在后；组里先顶层散歌，再逐个文件夹）
- **关掉窗口不会停播**，音乐照放；再点「音乐」按钮回到窗口
- 歌单**每次打开窗口时重扫一遍**，所以往任一处音乐文件夹里丢一首歌，下次开窗口它就在列表里——不用改代码，也不用重启
- 正在放的那首会**自动展开所在的组和文件夹并高亮**，手动展开过的也会记住，重扫之后不会又缩回去

### 歌从哪来

歌有**两处来源**，歌单里分成两组列着，各归各的：

| 组 | 位置 | 说明 |
| --- | --- | --- |
| **我的音乐** | `%APPDATA%\Godot\app_userdata\Self-Talk-Five-In-A-Row\music\` | 玩家自己的。窗口上那个「打开文件夹」按钮直接跳过去；**导出成 exe 之后这里照样能写**，想加歌就加在这儿 |
| **出厂音乐** | 工程的 `music/` | 跟着游戏一起打包的那批 |

```
出厂的 music/
├── 测试/                    ← 目前 24 首都在这里，歌单里显示「测试（24）」
└── 价值/ 存在/ 心灵与身体/ 知识/ 自定义/ 自由意志/ 语言与实在/
							 ← 目前都是空的，歌单里显示「xxx（空）」，点开写着「这个文件夹里还没有歌」
```

- 两组**不合并**：同名文件夹也各归各的（两边都有「测试」的话会各占一行），
  这样一眼能分清哪些是自己放的
- 播放顺序：**我的音乐在前**，出厂音乐在后；组里还是先顶层散歌、再逐个文件夹
- 歌单**只分一层**：根目录的直接子文件夹各占一行。再往深了放也算数，
  只是会归到它所属的那个顶层文件夹名下
- 认 `mp3` / `ogg` / `wav` 三种格式（Godot 4 运行时能加载的就这三种）
- 曲名取文件名（不含扩展名），**不解析 ID3 标签**；鼠标停在歌单某一行上会显示它的路径
- 空文件夹里的 `.gitkeep` 只是占位（git 不跟踪空目录），不会出现在歌单里
- 玩家那个目录一首歌都没有时，歌单里给一行灰字指路，而不是干巴巴一个「（0）」

> **导出成 exe 之后**，出厂的 `music/` 是打包进资源里的只读内容，但**你自己那个 `music/`
> 不受影响**——加歌删歌随时都行，下次开窗口就重扫。另外 `.gitkeep` 不是资源、不会被打包，
> 所以出厂那几个空文件夹在导出后就不存在了。这两点都是打包游戏的固有性质，不是缺陷。

## 设置

点棋盘左上角那个小号的「设置」按钮打开。**改动立刻生效、立刻写盘**，所以没有保存按钮。

| 项 | 作用 |
| --- | --- |
| 玩家执黑先手 | 打开＝玩家执黑先手（默认）；关掉＝玩家执白后手，对手执黑先下。**下一局生效** |
| 对手启用局面评估 | 换用「整个盘面的好坏」来取舍，而不是只看单个点 |
| 对手两层搜索 | 再推一步「玩家最好的应手」，能看穿一手做成的复合威胁；勾上会自动把局面评估也勾上 |
| 禁手规则 | **黑棋**走出三三 / 四四 / 长连**立即判负**（先后手对调时黑棋在对手手里，它也会避开禁手点） |
| 棋盘底色 / 格线颜色 / 窗口背景 | 三处配色，背景色几个窗口共用。点色块会弹出**独立的取色窗口**（色板 / 色相条 / RGB-HEX） |
| 界面控件 | 按钮、滑条、歌单这些控件的底色。**默认是半透明的深灰**——半透明才能和窗口背景融在一起，所以色块上会看到棋盘格，那是「这里是透明的」的正常提示，不是花屏。注意：**取色器不保留半透明**，用它挑过一次颜色之后 alpha 会被拍成 1、控件就变成实色了 |
| 恢复默认 | 把上面所有项退回默认值 |

文字颜色**不单独设**，它跟着窗口背景的明暗自动取反（浅底配深字、深底配浅字）；按钮上的字再跟着**控件底色**的明暗走一遍，所以把控件调成浅色时，按钮上的字会自动变深。

除了先手，其余项**默认全关／默认配色**，也就是保持最初那套手感——「界面控件」那个默认值就是 Godot 默认主题用的颜色，不动它的话控件外观和以前一模一样。

## 禁手规则（可选，默认关）

参考连珠（Renju）规则，**黑棋**额外受限，白棋不受限：

- **三三**：一手同时做出两个活三
- **四四**：一手同时做出两个四
- **长连**：连成六子及以上

开启后黑棋走出以上任意一种**立即判负**，状态栏会写明是哪种、是哪一方判负，并用红圈标出犯规处。相应地，黑棋只有**正好五连**才算胜（六连不再算胜）。

一步棋如果**连成了五**，那它优先算胜，不再看它是不是同时做出了两个四——这是正式规则的做法，游戏里也是这么判的。所以「四四」只针对那步没连成五的棋。

> 说明：这是禁手的**基础判定**。正式规则里还有「假活三」（看着是活三、实际因为堵点变不成活四）这类细节，本版按定义直接算，不处理这些例外。

## 对手的下法

先走硬规则，再按开关决定怎么挑点。硬规则（一直生效）：

1. 自己能连五 → 直接赢
2. 玩家能连五 → 必堵
3. 自己能做活四 → 堵不住
4. 玩家能做活四 → 先用冲四抢先手，否则堵住

第 5 步「挑点」分三档，由设置里的开关决定：

| 档位 | 做法 | 实测每手耗时 |
| --- | --- | --- |
| 默认 | 棋型分值 + 一步反制惩罚 | 约 60 ms |
| 局面评估 | 改用「走完之后整个盘面有多好」来比较 | 约 100 ms |
| 两层搜索 | 我一手 → 玩家最好应手 → 局面分，带 alpha-beta 剪枝 | 约 240 ms |

（耗时是在一个 16 子的中局盘面上实测的，机器不同会有出入。）

棋力参考：对随机落子约 10 手取胜；两个相同的实例互下会走成满盘和棋。**关于两层搜索的诚实说明**：它在「一手做成的四三」这类局面上能选出正确防守点，但在我构造的测试局面里，默认档也守住了——也就是说这个体量下它带来的棋力提升不明显，代价却是四倍耗时。更深的复合威胁（分两手铺垫的四三、连续冲四）两层搜索同样看不见，要解决得上专门的威胁空间搜索。

## 每局一个话题（对手说什么）

对手不是重复几句口头禅，而是**每一局说一个话题**：

- 开局挑一个话题（怎么挑见下）
- 话题正文**一句一句**在它落子时说（落一子说一句）
- 正文说完、棋还没下完 → 从**所有话题共用的垫场句池**随机取话
- **棋局结束，话题就结束**：没说完的正文直接作废，换成一句**告别语**
- 对话窗口**每局清空**，底部显示「话题：xxx · 已说 N 句」

台词全写在 `topics.txt` 里，跟代码分开。

### 话题怎么挑

三种情况，从前往后判：

1. **对话窗口还锁着**（还没赢过第一把）→ **不开话题**，也不推进任何抽取进度。
   反正看不到，说了只是白攒。
2. **玩家赢过之后的下一局** → 固定说「**特别话题 N**」，N 是这是第几次赢（1～5）。
   特别话题按顺序一个个放出来，**每个只说一次**；五次之后回到随机。
   只写了前三个也没关系，第 4、5 次赢之后照样随机。
3. **其余情况** → 从普通话题里**随机抽**，而且**一轮抽完之前不重复**
   （洗牌袋：把话题打乱排成一队，挨个取；取完了重新洗一队。
   新一队的开头还会避开上一队的结尾，免得听感上"连着说了两遍"）。

抽取进度写在存档里，关掉游戏再开是接着抽，不是从头来。

### 特别话题

用 `### 特别话题 3：标题` 起头，编号 1～5，对应「玩家第几次赢之后」。
写法、变量、结束语都和普通话题一样，只是抽取时机固定：

```
### 特别话题 1：首胜之后
行，第一把我认了。
再来一局，这回我先紧一紧。
```

### 告别语：按棋局长短分七档，按胜负分两路

告别语不写死一句，而是两个维度一起挑：

- **长短**：按**整局总棋子数**分七档 `10 / 16 / 24 / 32 / 64 / 128 / 256`。一局十手就被速杀，和一局下满 200 多手，说同一句话会很出戏。用总棋子数而不是「第几手」，所以先后手对调不影响分档
- **胜负**：同一档里再分**玩家赢**和**玩家输**两种情况各写一份——它是赢家和输家，语气不可能一样

不写胜负标记的那一行是**兜底句**，两种结果都能用（也用在和棋上）。

棋盘一共 225 个点，所以最上面那档 `256` 其实一辈子不会正好卡上，它的意思是「128 子以上、以及满盘和棋都归这一档」，一般只写一行不带标记的；真在最后一手分出胜负的极罕见情形也走这一行，所以别把话说死。

### 文件放哪儿

| 位置 | 说明 |
| --- | --- |
| `topics.txt`（工程根目录） | 出厂自带的**示例**内容，建议直接替换成你自己写的 |
| `user://topics.txt` | 你自己的那份，Windows 上是 `%APPDATA%\Godot\app_userdata\Self-Talk-Five-In-A-Row\topics.txt`。**存在就优先用它**，不用改工程、不用重新导出 |

**每局开始时自动重读一次**，所以改完下一局就生效——不用重启，也没有「重载」按钮。文件缺失或解析失败会退回内置的占位台词，对话窗口底部会写出错原因。

### 格式

```
// 以 // 开头的是注释，空行忽略

=== 垫场                    ← 所有话题共用的垫场句池
正文说完、棋还没下完时，从这里随机取一句

=== 结束 32 玩家赢          ← 写在所有话题之前 = 「通用池」，任何话题都用得上
=== 结束 32 玩家输          ← 同上，玩家输了
=== 结束 32                 ← 不写标记 = 两种结果都能用的兜底句

### 话题：标题              ← 一个普通话题；可以写很多个，随机抽，一轮不重复
### 特别话题 1：标题          ← 玩家第 1 次赢之后的下一局固定说这个（编号 1～5）

一行一句台词                ← 话题正文；对手每落一子说一句，写多长都行

=== 结束 32 玩家赢          ← 写在某个话题之后 = 只归它，只有说到它时才用
```

要点：

- 告别语分**两层**，写在哪儿决定归谁：写在某个话题之后的**只归它**，写在所有话题之前的进**通用池**。挑的时候**话题自己的先算**，它没写这一档就落到通用池。只想写一份通用的话，就全放在所有话题前面
- 某档没写 → 自动找**更大**的、写得有的档；更大的都没有，才退回任意一档；七个档一个都没写 → 不说告别语（主窗口仍有胜负提示）
- 某一档写了，但没写这个结果的那一路 → 用同档的兜底句；兜底句也没有 → 往更大的档找
- 一档一路写多句 → **随机取一句**。建议句数递减，例如每边 `4 → 10 句、8 → 9 句、16 → 8 句、32 → 7 句、64 → 6 句、128 → 5 句`：局越短越意外，能说的话反而越多
- **没有「段落收束句」这个概念**，正文就是一路逐句说下去
- 正文没说完棋就结束了，剩下的**直接丢掉**，不补说
- 对话窗口里的话**不带说话人名字**（一个窗口本来就只有一个说话的人），直接显示台词本身；台词里的方括号也按字面显示，不会被当成格式标记

### 台词里能用的变量

| 变量 | 含义 |
| --- | --- |
| `{move}` | 当前总手数 |
| `{cell}` | 对手这一手的落点，如 `H8` |
| `{player_move}` | 玩家上一手的落点 |
| `{my_score}` | 对手累计胜场 |
| `{player_score}` | 玩家累计胜场 |
| `{draws}` | 和棋数 |
| `{topic}` | 话题标题 |

用不到的可以不写。**写错的变量名会原样留在句子里**（漏写成 `{Player_move}` 就会看见 `{Player_move}`），方便发现笔误。

### 写完之后怎么检查

没有单独的校验工具，靠这三处就够了：

- **对话窗口底部**：解析出错会显示出错原因（消息里带着行号，比如「第 12 行 认不出的胜负标记」）
- **局中看正文**：开局后对手每落一子应该按顺序念正文；如果一上来就是「（占位台词）……」，说明文件根本没读到——检查路径和文件名拼写
- **局末看告别语**：如果不说告别语，说明这个档位（和它下面所有档位）连一句兜底句都没写；如果句子里带着 `{xxx}` 没被替换，就是变量名写错了

七个档建议都写，而且**赢、输各写一份**；至少每档留一句不带标记的兜底句。

## 成绩与存档

所有存档都在同一目录，Windows 上是：

```
%APPDATA%\Godot\app_userdata\Self-Talk-Five-In-A-Row\
```

| 文件 | 内容 |
| --- | --- |
| `score.cfg` | 总比分和总局数（ConfigFile 文本格式，可手改、可手抄） |
| `history.jsonl` | 每局一行 JSON：`{"time":"2026-09-27T14:03:11","result":"player","moves":43}`，`result` 取 `player` / `ai` / `draw` |
| `settings.cfg` | 先后手、三个棋力/规则开关、四处配色，以及**玩家看不见的进度**：随机话题抽到哪了（`[topics] bag` / `bag_pos`）、已说了几个特别话题（`[topics] special_played`）、窗口解锁到第几级（`[unlocks] level` / `all`） |
| `windows.cfg` | 四个窗口的位置、尺寸、开关状态 |
| `topics.txt` | **可选**。你自己写的台词；存在就优先用它，删掉就回到工程里那份示例 |

几点说明：

- **备份**就是复制这几个文件；**清空比分**用比分窗口里的「清空」按钮（有二次确认），旧明细会改名成 `history-<时间>.jsonl` **留档而不是删除**
- 想把自己的台词也一起备份，记得连 `topics.txt` 一起复制（它跟台词文件是两回事：**台词不会因为清空比分而丢**）
- 目录名取自 `project.godot` 里的 `application/config/name`，所以**改工程名会让存档看起来「被清零」**（其实是换了目录，老文件还在原处）
- 读取一律容错：文件缺失、被改坏、字段类型不对，都当作 0 或默认值处理，不会让游戏崩。取值不直接用 `int()` / `bool()` 这类构造器——Godot 的 `bool()` 碰上被手改成 `"true"` 的字符串会直接报错并打断整次读盘，所以统一走 `config_store.gd` 里的类型检查
- 窗口位置如果落在所有显示器之外（比如拔掉了副屏），会被夹回主显示器，不会开到看不见的地方
- 三套存档里**只有窗口布局带版本号**：改动窗口设计时旧的位置和尺寸会变成错的，必须靠版本号整份作废。比分和设置不用——每个字段读的时候都有默认值，加字段本身就是向后兼容的

## 环境

Godot 4.7.2（Forward+ 渲染，Direct3D 12）。

- 主窗口 720 × 720，`canvas_items` 拉伸 + `aspect = expand`：**不留黑边**，窗口拉大时视口跟着变大，棋盘和按钮行重新居中；小尺寸时按比例缩小，不会挤坏
- 四个小窗口同样开了 `canvas_items` 内容缩放 + `expand`：拉大缩小时字和控件一起等比变化，多出来的区域由界面铺开
- 小窗口靠 `display/window/subwindows/embed_subwindows=false` 才是**真正独立的系统窗口**，能单独最小化、关闭；取色器那个弹层也依赖它（内嵌进小窗口会被裁掉，看起来就像点不动）
- 挂 `Node2D` 下面的 Control **锚点不生效**（Godot 会按「父级尺寸为 0」计算），所以主窗口里的位置和宽度都在 `main.gd` 的 `_layout()` 里算
- 布局存档 `window_layout.gd` 带版本号：改动窗口设计时把 `VERSION` 加一，旧记录会被忽略一次，窗口回到新的默认摆放
- 界面中文用系统字体（微软雅黑 / 思源黑体 / 黑体）渲染，因为 Godot 默认主题字体不含中文字形
