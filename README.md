# Self-Talk-Five-In-A-Row

**五子棋 · 人机对战** —— 用 Godot 4.7 + GDScript 写的单人对战五子棋。

一个棋盘主窗口，外加三个可以各自关掉、独立存在的小窗口（比分、对话、设置）。比分长期保存在玩家的用户目录里；对手**每局说一个话题**，落一子说一句，棋局结束话题也结束。先后手、对手棋力、禁手规则和界面配色都在设置窗口里开关，台词写在 `topics.txt` 里。

## 玩法

- 15 × 15 棋盘，在交叉点落子
- 默认**玩家执黑先手**；可以在设置里换成玩家执白后手（那样对手执黑先下）
- 横、竖、斜任意方向先连成五子者胜，棋盘下满判和棋
- 默认是自由规则，无禁手（长连也算胜）；打开「禁手规则」后按连珠规则判罚，见下文

操作：鼠标移到交叉点上会显示半透明预览，左键落子。棋盘上那个红点是对手的最后一手。

## 运行

需要 [Godot 4.7](https://godotengine.org/download)：

```bash
godot --path .
```

或者用编辑器打开 `project.godot` 后按 <kbd>F5</kbd>。

## 四个窗口

| 窗口 | 尺寸 | 说明 |
| --- | --- | --- |
| 主窗口 | 720 × 720 正方形 | 棋盘 + 一行状态提示 + 左上角「设置」小按钮 + 底部三个按钮 |
| 比分窗口 | 380 × 400 | 累计比分（玩家 / 对手 / 和棋）和最近一局摘要，可清空 |
| 对话窗口 | 380 × 400 | 对手每落一子在这里说一句；一局一个话题，结束时收尾 |
| 设置窗口 | 380 × 400 | 先后手、棋力开关、禁手开关、三处配色 |

三个小窗口**尺寸一致**，行为也一致：

- **都能自由缩放，且内容等比跟随**：拉大时字和控件一起放大，缩小时一起缩小；另外拉伸模式是 `expand`，多出来的区域由界面铺开，**不会出现黑边**
- **启动时回到上次的位置、尺寸和开关状态**：上次关掉的小窗口这次仍是关着的，点主窗口对应按钮就能打开
- 第一次启动（还没有记录时）三个小窗口会摞在主窗口右边**竖排，不会互相叠着**；屏幕右边放不下就自动挪到主窗口下方

主窗口同样不留黑边：棋盘会重新摆到正中，顶部提示行和底部按钮行跟着窗口宽度重新居中。

## 设置

点棋盘左上角那个小号的「设置」按钮打开。**改动立刻生效、立刻写盘**，所以没有保存按钮。

| 项 | 作用 |
| --- | --- |
| 玩家执黑先手 | 打开＝玩家执黑先手（默认）；关掉＝玩家执白后手，对手执黑先下。**下一局生效** |
| 对手启用局面评估 | 换用「整个盘面的好坏」来取舍，而不是只看单个点 |
| 对手两层搜索 | 再推一步「玩家最好的应手」，能看穿一手做成的复合威胁；勾上会自动把局面评估也勾上 |
| 禁手规则 | **黑棋**走出三三 / 四四 / 长连**立即判负**（先后手对调时黑棋在对手手里，它也会避开禁手点） |
| 棋盘底色 / 格线颜色 / 窗口背景 | 三处配色，背景色几个窗口共用；文字颜色会跟着背景明暗自动取反。点色块会弹出**独立的取色窗口**（色板 / 色相条 / RGB-HEX） |
| 恢复默认 | 把上面所有项退回默认值 |

除了先手，其余项**默认全关／默认配色**，也就是保持最初那套手感。

## 禁手规则（可选，默认关）

参考连珠（Renju）规则，**黑棋**额外受限，白棋不受限：

- **三三**：一手同时做出两个活三
- **四四**：一手同时做出两个四
- **长连**：连成六子及以上

开启后黑棋走出以上任意一种**立即判负**，状态栏会写明是哪种、是哪一方判负，并用红圈标出犯规处。相应地，黑棋只有**正好五连**才算胜（六连不再算胜）。

> 说明：这是禁手的**基础判定**。正式规则里还有「假活三」（看着是活三、实际因为堵点变不成活四）这类细节，本版按定义直接算，不处理这些例外。

## 对手的下法

先走硬规则，再按开关决定怎么挑点。硬规则（一直生效）：

1. 自己能连五 → 直接赢
2. 玩家能连五 → 必堵
3. 自己能做活四 → 堵不住
4. 玩家能做活四 → 先用冲四抢先手，否则堵住

第 5 步「挑点」分三档，由设置里的开关决定：

| 档位 | 做法 | 实测每手耗时 |
| --- | --- | --- |
| 默认 | 棋型分值 + 一步反制惩罚 | 约 60 ms |
| 局面评估 | 改用「走完之后整个盘面有多好」来比较 | 约 100 ms |
| 两层搜索 | 我一手 → 玩家最好应手 → 局面分，带 alpha-beta 剪枝 | 约 240 ms |

（耗时是在一个 16 子的中局盘面上实测的，机器不同会有出入。）

棋力参考：对随机落子约 10 手取胜；两个相同的实例互下会走成满盘和棋。**关于两层搜索的诚实说明**：它在「一手做成的四三」这类局面上能选出正确防守点，但在我构造的测试局面里，默认档也守住了——也就是说这个体量下它带来的棋力提升不明显，代价却是四倍耗时。更深的复合威胁（分两手铺垫的四三、连续冲四）两层搜索同样看不见，要解决得上专门的威胁空间搜索。

## 每局一个话题（对手说什么）

对手不是重复几句口头禅，而是**每一局说一个话题**：

- 开局从话题库里取一个话题
- 话题正文**一句一句**在它落子时说（落一子说一句）
- 正文说完、棋还没下完 → 从**所有话题共用的垫场句池**随机取话
- **棋局结束，话题就结束**：没说完的正文直接作废，换成一句**告别语**
- 对话窗口**每局清空**，底部显示「话题：xxx · 已说 N 句」

台词全写在 `topics.txt` 里，跟代码分开。

### 为什么按棋子数分七档

告别语按**整局总棋子数**分档随机取，而不是固定一句：一局 4 手就收场（被对手速杀）和一局下满 200 多手，说同一句话会很出戏。分档之后短局有短局的话、长局有长局的话，每档写多句还能每局不重样。

档位是固定的七个：`4 / 8 / 16 / 32 / 64 / 128 / 225`。判定用**总棋子数**而不是「第几手」，所以先后手对调不影响分档；`225` 是满盘和棋。

### 文件放哪儿

| 位置 | 说明 |
| --- | --- |
| `topics.txt`（工程根目录） | 出厂自带的**示例**内容，建议直接替换成你自己写的 |
| `user://topics.txt` | 你自己的那份，Windows 上是 `%APPDATA%\Godot\app_userdata\Self-Talk-Five-In-A-Row\topics.txt`。**存在就优先用它**，不用改工程、不用重新导出 |

**每局开始时自动重读一次**，所以改完下一局就生效——不用重启，也没有「重载」按钮。文件缺失或解析失败会退回内置的占位台词，对话窗口底部会写出错原因。

### 格式

```
// 以 // 开头的是注释，空行忽略

=== 垫场                    ← 所有话题共用的垫场句池
正文说完、棋还没下完时，从这里随机取一句

### 话题：标题              ← 一个话题；可以写很多个，逐局轮换

一行一句台词                ← 话题正文；对手每落一子说一句，写多长都行

=== 结束 32                 ← 本局在 32 子以内结束时说的告别语，随机取一句
```

要点：

- 某档没写 → 自动找**更大**的、写得有的档；更大的都没有，才退回任意一档；七个档一个都没写 → 不说告别语（主窗口仍有胜负提示）
- 一档写多句 → **随机取一句**。建议句数递减，例如 `4 → 10 句、8 → 9 句、16 → 8 句、32 → 7 句、64 → 6 句、128 → 5 句、225 → 4 句`：局越短越意外，能说的话反而越多
- **没有「段落收束句」这个概念**，正文就是一路逐句说下去
- 正文没说完棋就结束了，剩下的**直接丢掉**，不补说

### 台词里能用的变量

| 变量 | 含义 |
| --- | --- |
| `{move}` | 当前总手数 |
| `{cell}` | 对手这一手的落点，如 `H8` |
| `{player_move}` | 玩家上一手的落点 |
| `{my_score}` | 对手累计胜场 |
| `{player_score}` | 玩家累计胜场 |
| `{draws}` | 和棋数 |
| `{topic}` | 话题标题 |

用不到的可以不写。**写错的变量名会原样留在句子里**（漏写成 `{Player_move}` 就会看见 `{Player_move}`），方便发现笔误。

### 写完之后怎么检查

没有单独的校验工具，靠这三处就够了：

- **对话窗口底部**：解析出错会显示出错原因（消息里带着用的是哪个文件，比如「第 12 行认不出的标记」）
- **局中看正文**：开局后对手每落一子应该按顺序念正文；如果一上来就是「（占位台词）……」，说明文件根本没读到——检查路径和文件名拼写
- **局末看告别语**：如果不说告别语，说明这个档位和它下面所有档位都没写；如果句子里带着 `{xxx}` 没被替换，就是变量名写错了

七个档建议都写，哪怕每档只写一句。

## 成绩与存档

所有存档都在同一目录，Windows 上是：

```
%APPDATA%\Godot\app_userdata\Self-Talk-Five-In-A-Row\
```

| 文件 | 内容 |
| --- | --- |
| `score.cfg` | 总比分和总局数（ConfigFile 文本格式，可手改、可手抄） |
| `history.jsonl` | 每局一行 JSON：`{"time":"2026-09-27T14:03:11","result":"player","moves":43}`，`result` 取 `player` / `ai` / `draw` |
| `settings.cfg` | 先后手、三个棋力/规则开关、三处配色，以及**话题轮换到第几个**（`[topics] next`） |
| `windows.cfg` | 四个窗口的位置、尺寸、开关状态 |
| `topics.txt` | **可选**。你自己写的台词；存在就优先用它，删掉就回到工程里那份示例 |

几点说明：

- **备份**就是复制这几个文件；**清空比分**用比分窗口里的「清空」按钮（有二次确认），旧明细会改名成 `history-<时间>.jsonl` **留档而不是删除**
- 想把自己的台词也一起备份，记得连 `topics.txt` 一起复制（它跟台词文件是两回事：**台词不会因为清空比分而丢**）
- 目录名取自 `project.godot` 里的 `application/config/name`，所以**改工程名会让存档看起来「被清零」**（其实是换了目录，老文件还在原处）
- 读取一律容错：文件缺失、被改坏、字段类型不对，都当作 0 或默认值处理，不会让游戏崩
- 窗口位置如果落在所有显示器之外（比如拔掉了副屏），会被夹回主显示器，不会开到看不见的地方

## 环境

Godot 4.7.2（Forward+ 渲染，Direct3D 12）。

- 主窗口 720 × 720，`canvas_items` 拉伸 + `aspect = expand`：**不留黑边**，窗口拉大时视口跟着变大，棋盘和按钮行重新居中；小尺寸时按比例缩小，不会挤坏
- 三个小窗口同样开了 `canvas_items` 内容缩放 + `expand`：拉大缩小时字和控件一起等比变化，多出来的区域由界面铺开
- 小窗口靠 `display/window/subwindows/embed_subwindows=false` 才是**真正独立的系统窗口**，能单独最小化、关闭；取色器那个弹层也依赖它（内嵌进小窗口会被裁掉，看起来就像点不动）
- 挂 `Node2D` 下面的 Control **锚点不生效**（Godot 会按「父级尺寸为 0」计算），所以主窗口里的位置和宽度都在 `main.gd` 的 `_layout()` 里算
- 布局存档 `window_layout.gd` 带版本号：改动窗口设计时把 `VERSION` 加一，旧记录会被忽略一次，窗口回到新的默认摆放
- 界面中文用系统字体（微软雅黑 / 思源黑体 / 黑体）渲染，因为 Godot 默认主题字体不含中文字形
